# From word operations to the public Turing machine

The pinned Formal Conjectures question asks for one solver with a polynomial clock on every canonically encoded `GameInput`. Validity guards its equilibrium guarantee. An invalid typed game still needs a canonically encoded output within the clock. Words outside the image of the input encoder carry no obligation. Mathlib counts calls to `FinTM2.step` and requires the exact final configuration, including the initial local state and empty scratch stacks. ## Checked in Lean 4.36

`BitStacks.Program` is a finite instruction table over finitely many bit stacks. A branch can inspect or pop the top bit. A push writes one bit. `Program.step_embed` proves each instruction takes one Mathlib step. `Program.outputs` transports a clean execution with the same count. [Instruction semantics and compiler](BitStacks.lean)

`Delimiter.program` implements the public block encoder on two stacks. Moving an input bit to scratch takes two instructions. Writing it back with its prefix takes three. Detecting the two ends, seeding the terminator and halting take four further instructions. `Delimiter.steps` proves the exact count `5 * n + 4` for every raw payload. `Delimiter.polyTime` packages the program as a Mathlib polynomial-time machine. [Machine](Delimiter.lean) · [Public delimiter](https://github.com/google-deepmind/formal-conjectures/blob/9bd16c570aed942e00ae000c7522dd42ebbb25eb/FormalConjecturesForMathlib/Computability/BitstringEncoding.lean#L103-L115)

`exists_polyTime_bayesNash_of_runs` gives the public conclusion once a single program has polynomially bounded executions on all typed inputs and its outputs agree with the exact solver on valid games. The upstream replay checks the conclusion against the pinned source text, including the original encoders and `IsPolyTime` definition. ## Remaining refinement

A project `CompilerRun.Run` stores a value, a transition count and a maximum width. For every Lean function `f`, including one that produces exponentially many bits, `Run.ret (f x)` assigns zero transitions and width zero. Thus those fields alone cannot prove a machine running time. A solver refinement needs a fixed program, an encoding of its live records and addresses, and a simulation invariant relating its stores to the algorithm's states. Each arithmetic, comparison, indexed access, allocation and loop must execute on the representation. Summing the resulting step bounds may include polynomial overhead for scanning the represented memory. At exit the program must emit the canonical compact strategy and clear its scratch stacks. One permissible invalid-game branch returns the empty pair of lists, encoded as the single bit `false`. [Word model](../../StochasticGames/CompilerRun.lean) · [Existing binary composition](../InputOutput/CodecWorkSolver.lean)
